- `POST /api/rosters/generate`, `GET /api/rosters/{month}`, `POST …/edits`,
  `POST …/publish`, `GET …/export?format=csv`, `GET /api/audit`, and swap propose /
  accept / approve / reject plus `GET /api/swaps/{id}` so the script can see a lapse.
- The controller asks `AuthorizationPolicy`. Deny and RequiresApproval are HTTP 403,
  with the decision in the body. A rejected edit is 422 and writes no audit event.
- `staff1` is doctor `D01` and `staff2` is `D06`. On the generated November roster D02
  has no day shift that can be exchanged with D01 without a weekly off, a double-book, or
  a post-duty off. CSRF is off: the API is stateless, and the demo script posts with curl.
- `SwapLapseJob` calls `SwapLifecycle.lapseOpen` on `roster.lapse-delay-ms` (15s in dev).
- `CsvRosterExporter` is the minimum that makes the export step of the script work.
  PDF throws. It sits in `export`, which Yoogi owns, because that is where
  `RosterExporter` lives and no implementation had landed.
- `AccessControlTest`: staff edit of a draft is 403 and does not call `applyEdit`;
  admin edit is 200.

## What was wrong / what was checked

- Publish is not in the plan's list of eight calls. Without it a swap is denied, because
  the policy only allows swaps on a published roster. The script publishes before the swap.
- **Staff could not offer their own shift.** `InMemoryUserDetailsManager` wraps the login
  and drops `RosterUser`, so the doctor id never reached the policy. A plain
  `UserDetailsService` returns `RosterUser` instead. It returns a copy on every login:
  the filter erases the password on the object it authenticated, and the second request
  as the same user was then 401. `SecurityConfigTest.sameUserCanAuthenticateTwice` and
  `DevUsersConfigTest.staffLoginsKeepTheirDoctorId` cover both.
- `./gradlew test` for `AccessControlTest`, `SecurityConfigTest`, `DevUsersConfigTest`
  and `SwapLifecycleTest`: pass. PMD and SpotBugs on main: no findings.
- `ROSTER_DEV_PASSWORD=demo-pw ./demo/mid-demo.sh` against a dev `bootRun`: generate
  returned `ok` with soft penalty 13 and nothing unfilled. CSV starts
  `date,shift,staffId,name,post`. A double-book is 422 and the audit count stays put.
  A valid edit is 200. staff1 proposes a D01/D06 Shift II exchange, staff2 accepts,
  admin approves (`APPROVED`). A Shift I swap for 4 Nov is `LAPSED` by the job, and
  staff1 editing D02's published shift is 403.
